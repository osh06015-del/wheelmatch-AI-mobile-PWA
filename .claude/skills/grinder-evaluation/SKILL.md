# 판독 평가

**이 스킬은 평가 항목을 정의한다. 새 안전 판정 로직을 만들지 않는다.**

## 먼저 — 이미 있는 것을 쓴다

평가를 새로 설계하기 전에 **현재 테스트가 무엇을 이미 덮는지** 확인한다.
중복을 만들면 같은 것을 두 곳에서 관리하게 된다.

```
npm test
```

현재 23개 파일 346개가 통과한다. 판독 계층 관련은 특히 이 넷이다.

| 파일                                | 덮는 것                             |
| ----------------------------------- | ----------------------------------- |
| `src/lib/rules/engine.test.ts`      | 판정 규칙, 8종 시나리오, 경계값     |
| `src/lib/ocr/parser.test.ts`        | 단위 파싱, 환산, 치수 표기          |
| `src/lib/ocr/schema.test.ts`        | 모델 출력 계약, enum 이탈 거부      |
| `src/app/api/extract/route.test.ts` | 입력 검증, 오류 상태 (키 없이 동작) |

**이미 덮인 항목에 새 테스트를 겹쳐 쓰지 않는다.**

## 평가 항목

아래 일곱 가지를 본다. 각 항목마다 **자동으로 반복 가능한지** 표시했다.

### 1. 정상 · 저품질 · 지원하지 않는 이미지

| 경우                    | 기대 동작                        |
| ----------------------- | -------------------------------- |
| 정상 라벨               | 값 추출 → 규칙 판정              |
| 저품질(흐림·어두움)     | `confidence: low` → **판정불가** |
| 지원하지 않는 숫돌 형식 | `UNDETERMINED` (부적합 아님)     |

지원하지 않는 형식(다이아몬드·플랩디스크·컵휠·와이어브러시)이 **부적합으로
나오면 틀렸다.** "나쁜 숫돌"이 아니라 "이 앱이 판정할 수 없는 숫돌"이다.

**자동 반복:** 합성 값으로 가능 (현재 `engine.test.ts`가 덮음).
실제 이미지로는 실물 촬영이 필요 → 사람.

### 2. 라벨 잘림 · 반사 · 흔들림

읽지 못한 값이 `null`로 남고 판정불가로 이어지는지. 기본값·추정치로
채워지면 안 된다.

**자동 반복:** `null` 처리는 합성 값으로 가능.
실제 반사·흔들림 사진의 인식률은 **실물 촬영 필요 → 사람.**

### 3. 숫자와 단위 오인식

자리수 오독(12,200 → 1,220 / 122,000), 단위 혼동(rpm ↔ m/s),
지름 오독(Φ125 → Φ12.5).

현재 두 가지가 이를 잡는다.

- `checkPeripheralSpeed` — 계산된 가장자리 속도가 상식 범위(15~110 m/s) 밖이면 판정불가
- `checkUnitConsistency` — 라벨의 rpm 표기와 m/s 표기가 10% 넘게 어긋나면 판정불가

**15~110 m/s는 안전 한계가 아니라 오독 필터다.** 안전 기준으로 인용하지 않는다.

**자동 반복:** 가능.

### 4. 필수 정보 누락 · 상충

- 회전속도·지름이 없을 때 → 판정불가
- 두 표기가 서로 다를 때 → 어느 쪽도 믿지 않고 판정불가
- 대조할 상대가 없는 값(내경) → 판정하지 않고 사람에게 확인 요청

**자동 반복:** 가능.

### 5. 위험 조합 미검출 (false-safe)

**실제로는 부적합인데 적합으로 나오는 경우.** 이 앱에서 가장 중요한 지표다.

특히 위험한 오독 방향:

- 그라인더 rpm을 **낮게** 읽음 → RPM 검사가 그냥 통과
- 숫돌 지름을 **작게** 읽음 → 지름 검사가 그냥 통과

둘 다 조용히 "적합"을 만들어낸다. `src/lib/record/metrics.ts`의
`evaluate()`가 `falseSafe`를 별도로 계산하며, **판정불가는 여기 넣지 않는다**
(막은 것은 놓친 것이 아니다).

**자동 반복:** 합성 값으로 가능. **실제 false-safe율은 정답(Ground Truth)이
있어야 계산된다 → 사람이 정답을 적어야 한다.**

### 6. 판독 거부 · 확인 필요 상태

- `UNDETERMINED`가 실패가 아니라 **설계된 동작**으로 다뤄지는가
- `advisory`(경고)와 차단이 구분되는가
- 신뢰도 `low`가 사람의 확인으로만 풀리는가

**자동 반복:** 가능.

### 7. 표시된 결과와 근거의 연결

화면 판정이 실제 `checks` 내용과 일치하는가. 판정 근거를 되짚을 수 있는가.
`groupChecks()`가 확인됨/불일치/판독불가/직접확인으로 나눈다.

**자동 반복:** 가능 (`grouping.test.ts`).

## 지표

`src/lib/record/metrics.ts`가 네 가지를 **따로** 계산한다. 합치지 않는다.

| 지표                | 의미                                                 |
| ------------------- | ---------------------------------------------------- |
| `falseSafe`         | 실제 부적합인데 적합. **0이 아니면 출시하지 않는다** |
| `unreadable`        | 판정하지 못한 비율. 실패가 아니라 설계된 동작        |
| `fieldAccuracy`     | 필드 단위 인식 정확도 (원본값 기준)                  |
| `unitNormalization` | m/s → rpm 환산 오류율                                |

인식률은 **사용자가 고치기 전의 원본값**으로 잰다. 최종값으로 재면
사람이 고친 것까지 모델이 맞힌 것으로 계산된다.

## 코드로 할 수 있는 일 / 사람이 해야 하는 일

`docs/roadmap.md` 기준이다.

### 코드 (후속 개발 후보 — 이번 설정 작업에서는 실행하지 않는다)

- 데모 모드 (오프라인 시연)
- OCR 정확도 자동 계산 화면
- 규칙 버전 표시 (기준 문서명 확정이 먼저)
- 판정 근거를 결과·이력 화면에도
- 이력 작업별 필터
- 촬영 품질 게이트 / OCR 이중검증 / 하이브리드 OCR / 이미지 전처리

### 사람 — **자동 반복의 완료 조건에서 제외한다**

이것들은 에이전트가 끝낼 수 없다. 완료 조건에 넣으면 영영 끝나지 않거나,
더 나쁘게는 **없는 결과를 만들어내게 된다.**

- **실물 20세트 촬영·측정** — 실제 장비와 숫돌이 필요
- **SUS 설문 응답 수집** — 5~10명의 실제 응답
- **원어민 번역 검수** — 4개 언어
- **QR 인쇄물 제작·현장 확인** — 실제 인쇄와 스캔
- **수기 vs 앱 소요시간 비교** — 사람이 초시계로

**측정값·설문 결과·전문가 확인을 만들어내지 않는다.**
정답(Ground Truth)이 없으면 `falseSafe`와 `fieldAccuracy`는 계산할 수 없다.
계산할 수 없으면 계산할 수 없다고 보고한다.

측정 절차는 `docs/validation-plan.md`에 있다.

## 하지 않는다

- **새 안전 판정 로직을 추가하지 않는다.** 이 스킬은 평가를 정의할 뿐이다.
- **출처 없는 평가 데이터를 만들지 않는다.** 법령·표준 인용은
  `docs/regulatory-sources.md`에 이미 기록된 것만 쓴다. `미확인` 항목은 미확인으로 둔다.
- 개인정보·실제 사용자 이미지·출처 불명 이미지를 fixture로 넣지 않는다.
- 실패한 테스트를 삭제하거나 약화하지 않는다.
