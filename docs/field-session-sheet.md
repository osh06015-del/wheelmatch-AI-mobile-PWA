# 조원용 측정 기록지

실행 절차는 [실물 검증 계획](rc-field-validation.md), 지표 정의는
[검증 계획](validation-plan.md)을 따른다. 이 파일은 **아직 실행하지 않은 빈 양식**이다.
문서 작성이나 자동 테스트 통과를 실물 검증 완료로 표시하지 않는다.

## 1. 세션 정보 — 시작 전에 기입

- 세션 ID:
- 측정일 / 기록자 / 독립 정답 확인자:
- 데이터 종류: 실물 촬영 / 합성 이미지 (하나만 선택, 서로 별도 세션)
- 앱 URL / 화면 Build SHA / 규칙 버전:
- 휴대폰 모델 / OS / 브라우저·버전 / PWA 여부:
- 조명·거리·반사 등 촬영 조건:
- 정답 근거 자료·제품 라벨 사진의 로컬 위치:
- 연습 시도 ID (본 측정에서 구분):

공유 전에 사진 속 작업자·사업장 등 불필요한 개인정보가 없는지 확인한다.
측정 도중 앱 버전·기기·주소를 바꾸면 새 세션을 만든다. 같은 실물의 반복 촬영은
새로운 독립 제품 표본이 아니므로 제품 ID와 시도 ID를 따로 붙인다.

## 2. 전체 시도 대장 — 저장하지 못한 시도도 한 줄

| 시도 ID | 실물/이미지 세트 ID | 작업 목적 | 정답 사전 확정 | 종료 상태 | 앱 판정 | 저장 recordId | 사전점검 시간 | 메모·증거 |
| ------- | ------------------- | --------- | -------------- | --------- | ------- | ------------- | ------------- | --------- |
|         |                     |           |                |           |         |               |               |           |

- 종료 상태: 미실행 / 저장 완료 / Gate 차단 / 분석 실패 / 사용자 중단 / 기타 오류.
- 앱 판정: 실제 표시된 값만 기록. 결과 화면에 도달하지 않았으면 **미관찰**.
- 저장 recordId: 같은 기기·브라우저·URL의 기록과 연결한다. 미저장은 **없음**.
- 시간은 단위(ms 또는 초)를 표시한다. 앱 내부 시간과 외부 초시계를 섞어 평균내지 않는다.
- 중단·차단을 성공 저장으로 만들려고 답을 바꾸거나 상태 확인을 허위로 체크하지 않는다.
- 위험 조합은 입력·판정의 차단 여부를 관찰하는 자료다. 장착·가동을 유도하는 절차가 아니다.
  앱 타이머 완료를 실제 장비 시험운전의 증거로 기록하지 않는다.

## 3. 시도별 정답·관찰 상세 — 필요한 만큼 복사

**시도 ID / 세트 ID:**

앱 결과를 보기 **전에** 독립적으로 기록:

- 그라인더 모델 / 무부하 RPM / 최대 지름(mm):
- 부속품 종류 / 최고사용 RPM / 지름(mm):
- 용도·유효기한·덮개 등 해당 판정에 필요한 추가 조건:
- 독립 정답 판정 / 이유 / 근거 위치 / 확인자:
- 모르는 값과 확인하지 못한 조건:

앱 사용 중·후에 기록:

- 촬영 조건 / 재촬영 횟수 / 사진 품질 경고:
- 원본 OCR 오독·미인식 필드 / 작업자가 고친 값:
- Gate 차단·제한 대조(직접 입력 / 기기 안 OCR / 버린 판독)·제한적 Profile 등 판정 또는 중단 이유:
- 사전점검 시간 / 전체 흐름 시간 (시험운전 시간과 분리):
- 저장 성공 여부 / recordId / 증거 화면 파일명:
- 막힌 화면 / 기대한 다음 행동 / 실제로 누른 행동:

## 4. 기존 평가 화면에 연결

1. 동일 세션의 백업 JSON과 검증판 CSV를 별도로 보관한다. 백업은 사진을 포함하지
   않으므로 정답 라벨 사진·실패 화면은 위의 증거 위치에 따로 보관한다.
2. 기존 평가 화면의 정답 JSON에는 저장된 recordId와 사전에 적은 정답만 연결한다.
   키는 `recordId`, `grinderRPM`, `grinderMaxDiameter`, `wheelMaxRPM`,
   `wheelDiameter`, `verdict`다. 숫자 단위는 rpm·mm, 모르는 숫자는 `null`,
   판정은 `COMPATIBLE` / `INCOMPATIBLE` / `UNDETERMINED`다.
3. 같은 recordId를 두 번 넣지 않는다. 중복 ID의 유효한 행은 정답이 같아도 전부
   제외되고 제외 수가 표시된다. 값은 양수 또는 `null`, ID는 양의 안전한 정수여야 한다.
   새 파일을 선택하면 이전 평가는 비워지고 파일명·읽기 상태가 표시된다.
   서로 다른 기기·주소의 recordId는 충돌할 수
   있으므로 정답 파일과 백업을 합쳐 업로드하지 않고 세션별로 평가한다.
4. 표시된 수치는 **저장·정답 연결된 표본**의 지표다. 전체 시도 대장에서 차단·실패·중단
   수를 별도로 함께 보고한다. 미저장 사례에 임의 recordId나 가짜 판정을 만들지 않는다.

## 5. 발표용 집계 — 실측 후에만 채우기

- 전체 시도 / 미실행 / 저장 / 차단 / 실패·중단:
- 서로 다른 실물 제품·조합 수 / 반복 촬영 수:
- 정답과 연결한 기록 수 / 제외 수·이유:
- 필드 정확도: 일치 필드 / 채점 필드. 미인식과 오독도 분리:
- False-Safe: 부적합 정답 중 앱 적합 / 부적합 정답 수:
- 부적합 정답 중 앱 부적합 / 앱 판정불가 / 미관찰 수:
- 판정불가율 / 환산 RPM 불일치율(평가 화면 표기 「단위 정규화 오류」): 각각 분자·분모:
- 사전점검 시간 개별값·중앙값 / 비교 수기 점검의 동일 시작·종료 기준:
- 발견한 사용성 문제 3개 / 실제 개선 전후 증거:

분모가 없으면 N/A. 합성 이미지 성과는 실물 인식률로 발표하지 않는다.
작은 표본의 False-Safe 0건은 해당 표본의 관찰 결과이지 안전 보증이나 일반화된 0%가 아니다.
