# 9월 30일까지 로드맵

작성 2026-09-01. 남은 기간 약 4주.

## 우선순위 원칙

1. **안전 결함이 먼저다.** 지금 조용히 틀린 답을 내는 경로가 있다.
2. **제안서가 약속한 검증은 발표 필수다.** 코드보다 실측이 부족하다.
3. **제안서에 쓴 주장은 구현으로 뒷받침해야 한다.** 말만 있으면 질문받는다.
4. 남는 시간에 데모 품질을 올린다.

시간은 AI 보조 개발 기준이다. 논문·슬라이드 작성 시간은 별도다.

## A. 안전 결함 — 반드시 (합계 ~5시간)

### A-1. 물리 교차검증 (~2시간) ★ 최우선

제안서 주요기능에 **"RPM·지름·용도 교차검증"** 이라고 썼는데, 지금은 세 값을
각각 따로 볼 뿐 서로 대조하지 않는다. "교차"가 없다.

원주속도로 교차검증이 가능하다.

```
v = π × d[m] × rpm / 60
```

사양서 20세트를 계산해보면 정상 조합은 전부 **55~80 m/s**에 모인다.
상용 숫돌 정격이 그 대역에 설계되어 있기 때문이다.

| 조합                  | 원주속도 |
| --------------------- | -------- |
| Φ125 / 12200rpm       | 79.8 m/s |
| Φ100 / 15300rpm       | 80.1 m/s |
| Φ180 / 8500rpm        | 80.1 m/s |
| Φ125 / 8500rpm (연삭) | 55.6 m/s |

OCR이 자릿수를 틀리면 이 대역을 크게 벗어난다.

| 오인식                      | 계산 결과 |
| --------------------------- | --------- |
| `12200` → `1220` (0 빠짐)   | 8.0 m/s   |
| `12200` → `122000` (0 추가) | 798 m/s   |
| `Φ125` → `Φ25`              | 16.0 m/s  |

**자릿수 오인식은 이 앱에서 가장 위험한 실패다.** 8500을 85000으로 잘못 읽으면
부적합 숫돌이 적합으로 나온다. 물리 법칙으로 이걸 잡는다.

구현 규칙 — **의심만 추가하고 통과시키지 않는다.**

- 대역 안 → 아무것도 바꾸지 않는다 (통과 근거로 쓰지 않는다)
- 대역 밖 → **판정불가** + "숫자를 다시 확인하세요"
- 이미 부적합인 것을 적합으로 되돌리는 경로는 만들지 않는다

> 착수 전 확인: 80 m/s 상한은 상용 결합숫돌 통례다. KS/EN 12413 실제 조문을
> 확인해 대역을 확정하고, 근거를 주석에 남긴다. 추측한 숫자를 안전 규칙으로
> 넣지 않는다.

### A-2. 미지원 숫돌 종류 감지 (~1시간)

지금 `purpose`는 `cutting | grinding | unknown` 셋뿐이다. 다이아몬드 컵휠,
와이어 브러시, 플랩디스크를 찍으면 **앱이 절단/연삭 규칙을 그대로 적용한다.**
조용히 틀린 답을 낸다.

제안서는 "모든 제조사와 특수 숫돌"을 제외했다. 제외를 지키되,
**지원하지 않는 종류를 알아채고 멈추는 것**은 필요하다.

- 스키마에 종류 필드 추가 (컵휠/와이어브러시/플랩디스크/기타)
- 미지원 종류 → 판정불가 + "이 앱은 이 종류를 다루지 않습니다"

### A-3. 명백한 파손 경고 (~1.5시간)

제안서는 "사진만으로 균열·미세손상 판정"을 제외했다. 미세균열은 사진에
보이지 않고 표준은 타음검사이므로 전면 도입은 안 된다.

**방향을 하나만 연다.**

| 방향                              | 허용         |
| --------------------------------- | ------------ |
| 명백한 파손이 보임 → 경고         | ✅           |
| 파손이 안 보임 → "손상 없음" 승인 | ❌ 절대 금지 |

깨진 모서리나 큰 균열은 사진으로도 보인다. 잡으면 이득, 못 잡아도 현재와 같다.
손해 볼 수 없는 구조다.

## B. 제안서 검증 방법 — 발표 필수 (합계 ~6시간 + 실측 시간)

제안서 검증 방법 3개가 현재 **전부 미실시**다. 여기가 가장 큰 구멍이다.

### B-1. 20세트 측정 하네스 (~3시간)

> 규격이 확인된 기계·숫돌 조합 20세트를 구성해 필드 추출 정확도와
> 부적합 탐지 재현율을 측정한다.

사진 폴더 + 정답 CSV를 넣으면 자동으로 표를 뽑는 스크립트.

- 필드별 정확도 (모델명 / RPM / 지름 / 두께 / 용도)
- 판정불가 비율
- 호출당 소요시간
- 오답 목록 (어떤 사진에서 무엇을 틀렸는지)

**실험 설계 요점:** 판정이 결정론적 규칙이므로
**부적합 탐지 재현율 = 필드 추출 정확도**다. 추출만 맞으면 판정은 항상 맞는다.
그래서 재야 할 것은 하나뿐이고, "판정 오류"와 "인식 오류"를 분리해 보고할 수 있다.

### B-2. 앱 내 소요시간 측정 (~1시간)

> 수기 확인과 앱 확인의 평균 소요시간을 비교한다.

앱이 스스로 재면 데이터 수집이 쉬워진다. 시작~저장까지 경과시간을
점검 기록에 함께 저장하고, 이력 화면에 평균을 보여준다.

수기 확인 시간은 사람이 초시계로 재야 한다.

### B-3. SUS 설문지 (~1시간, 문서)

> 5~10명 대상 SUS 사용성 설문

표준 10문항 한국어판을 만들고 채점표를 붙인다. 코드가 아니라 문서다.

## C. 제안서 주장 뒷받침 (~6시간)

### C-1. 다국어 UI (~5시간) ★

제안서 기대효과에 이렇게 썼다.

> 명판을 읽기 어려운 초보·**외국인 작업자**의 사전점검 지원

그런데 UI 문자열 110개가 전부 한국어이고 다국어 처리 코드가 0줄이다.
**지금 상태로는 외국인 작업자가 앱 자체를 못 읽는다.** 발표에서 이 문장을
말하면 "어떻게요?"라는 질문이 바로 나온다.

- 문자열을 한 곳으로 모으고 언어별 파일로 분리
- 한국어 + 영어를 먼저, 여력 되면 베트남어
- 판정 3색(적합/부적합/판정불가)은 색과 아이콘으로도 구분되므로
  글자를 못 읽어도 최소한의 정보는 전달된다

### C-2. 큰 글씨 / 고대비 모드 (~1시간)

현장·야외·노안을 고려한 접근성. 이미 최소 16px, 터치 48px은 지켰으므로
배율 토글만 추가하면 된다.

## D. 현장 실용성 (합계 ~10시간)

### D-1. 하이브리드 OCR (~4시간)

`docs/offline-ocr.md`의 실측 결과에 따른 후속.

```
사진 → 온디바이스 OCR → 신뢰도 높음 → 그대로 (무료·1초·오프라인)
                      → 낮음 → Claude 호출
```

깨끗한 라벨은 공짜로 처리되고 어려운 사진만 API를 쓴다.
네트워크가 끊겨도 앱이 죽지 않는다. `OCRExtractor` 인터페이스가 이미 있어
`HybridExtractor` 하나만 추가하면 UI는 건드리지 않아도 된다.

### D-2. 이미지 전처리 (~4시간)

기울기 보정 + 적응형 이진화 + 대비 스트레칭.
Tesseract 정확도가 크게 오르고 Claude 인식률도 올라간다.
실측에서 현장 사진 Tesseract 실패의 상당수가 여기서 살아날 것으로 보인다.

### D-3. 점검 기록 내보내기 (~1.5시간)

IndexedDB의 기록을 CSV/JSON으로 저장. **연구 데이터 수집에 직접 쓰인다.**
B-1 측정과 함께 쓰면 논문 표를 그대로 만들 수 있다.

### D-4. 저장된 사진을 이력에 표시 (~30분)

지금 사진을 저장하지만 어디에서도 보여주지 않는다. 저장공간만 쓰고 있다.
표시하면 "이때 이 라벨을 찍었다"는 증빙이 되어 점검 기록으로서 가치가 오른다.

## E. 발표·데모 품질 (합계 ~5시간)

### E-1. 데모 모드 (~2시간) ★ 발표 안전장치

발표장 네트워크는 자주 불안하다. API가 안 되면 시연이 통째로 실패한다.

- 샘플 라벨 이미지를 앱에 내장
- 네트워크·API 없이 전체 흐름 시연
- 적합 / 부적합 / 판정불가 3가지 결과를 버튼 하나로 재현

**이건 보험이다. 우선순위를 낮게 두지 말 것.**

### E-2. 통계 화면 (~2시간)

총 점검 수, 판정별 비율, 평균 소요시간. 발표 슬라이드에 그대로 쓸 수 있다.

### E-3. 결과 공유 (~1시간)

결과 화면을 이미지나 텍스트로 내보내기. 카톡 공유는 이미 된다.
