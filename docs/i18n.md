# 다국어 — 현재 상태와 남은 일

지원 언어: 한국어 · English · Tiếng Việt · Bahasa Indonesia · 中文(간체)

## 반드시 먼저 알아야 할 것

**한국어 외 4개 언어는 아직 검수를 받지 않았다.** 기계 번역이 아니라 사람이
읽을 수 있게 다듬은 문장이지만, 원어민이 확인한 적은 없다. 현장에 내보내기 전에
검수가 필요하다.

2026-09-16에 핵심 흐름 전체(촬영·값 확인·검사 사유·이력·연구 도구·오류)를 5개
언어로 옮겼다. **새로 옮긴 문장도 원어민 확인을 받지 않았다.** 문구 파일의 키가
모두 채워졌다는 것은 화면이 고른 언어로 끝까지 이어진다는 뜻이지, 번역이
맞다는 뜻이 아니다.

앱은 이 사실을 숨기지 않는다. 한국어가 아닌 언어를 고르면 화면에
"번역문은 검수 전입니다. 뜻이 갈리면 한국어 원문을 따르세요"가 뜬다
(`translation.notice`). 검수가 끝나기 전에는 이 문구를 지우지 마라.

## 어디까지 번역했나

| 화면 요소                              | 5개 언어  | 비고                                              |
| -------------------------------------- | --------- | ------------------------------------------------- |
| 판정 (적합/부적합/판정불가) + 설명     | ✅        | 가장 중요한 문구                                  |
| 즉시 행동지침 (사용하지 마십시오 …)    | ✅        | 부적합일 때 뜨는 조치                             |
| 검사 항목 **이름**                     | ✅        | RPM 안전, 지름 호환 …                             |
| 검사 항목 **사유 문장**·비교 값        | ✅        | 엔진의 사유 코드로 만든다. 코드 없는 옛 기록은 ❌ |
| 결과의 4분류·여유율·규격 요약          | ✅        | 맞지 않는/읽지 못한/직접 확인할/확인된 정보       |
| 안전 체크리스트 3개 (제목 + 설명)      | ✅        | 체크해야 저장이 열린다                            |
| 작업 직전 불꽃 방향 안내               | ✅        |                                                   |
| 면책 문구 · 규칙 근거(출처)            | ✅        | 법령 이름·조항도 번역. 문서번호·시행일은 그대로   |
| 메인 화면 (작업 선택)                  | ✅        |                                                   |
| 촬영·분석·값 확인 화면                 | ✅        | 항목 이름·설명·신뢰도·필요 숫돌 조건              |
| 숫돌 종류 선택지·안내 (값 확인 화면)   | ✅        | AI 제안과 다르면 직접 확인                        |
| Grinder / Wheel Condition · 시험운전   | ✅        |                                                   |
| 결과 화면 버튼·안내 · 작업별 위험사항  | ✅        | 재촬영, 저장, 오류                                |
| 점검 이력 화면                         | ✅        | 소요시간 단위까지                                 |
| 연구 도구 (검증 빌드)                  | ✅        | 안내 문구·지표 이름·정의                          |
| 카메라·사진 형식·네트워크·API 오류     | ✅        | 서버 문장이 아니라 실패 종류로 문장을 고른다      |
| 탭 제목 · 문서 언어(`<html lang>`)     | ✅        | `DocumentLocale`이 브라우저에서 바꾼다            |
| 검색·공유 카드 메타데이터, 공유 이미지 | ❌ 한국어 | 서버가 고정으로 그린다. 작업 흐름 밖              |
| 모델 지시문 · 서버 로그용 오류 문장    | ❌ 한국어 | 작업자에게 보이지 않는다                          |

사유 문장은 이렇게 옮긴다. 규칙엔진은 번역을 모른 채 한국어 사유(`reason`)와 함께
**사유 코드**(`detail.code`)와 문장에 들어갈 값(`detail.params` — 숫자·날짜·코드만)을
낸다. 화면(`checkText.ts`)이 그 코드로 고른 언어의 문장을 만든다. 한국어 문구는
엔진 문장과 글자까지 같아야 해서, `checkText.test.ts`가 엔진이 낼 수 있는 조합을
넓게 돌려 전부 대조한다.

이 기능 도입 전에 저장된 기록에는 사유 코드가 없다. 그런 기록의 사유는 어느
언어에서나 저장된 한국어 그대로 보인다 — 빈 칸보다 낫고, 기록을 고쳐 쓰지 않는다.

## 자체 점검에서 고친 것 (2026-09-02)

번역을 처음부터 다시 읽으며 고친 것들이다. 원어민 검수를 대신하지는 못한다.

| 언어 | 고친 것                                                     | 이유                                                                 |
| ---- | ----------------------------------------------------------- | -------------------------------------------------------------------- |
| vi   | `kiểm duyệt` → `hiệu đính`                                  | **오역.** `kiểm duyệt`는 '검열'이다. 번역 검수는 `hiệu đính`이다     |
| vi   | `Trang đầu` → `Trang chủ`                                   | `Trang đầu`는 '첫 페이지'. 홈은 `Trang chủ`                          |
| vi   | `công trường` → `nơi làm việc`                              | `công trường`은 건설현장만 뜻한다. 원문 '사업장'은 공장도 포함한다   |
| id   | `kecepatan tepi` → `kecepatan keliling`                     | 원주속도의 정식 용어                                                 |
| zh   | `作业前` → `就在开始作业前`                                 | 원문 '작업 **직전**'의 시점이 빠져 있었다. 이 문구는 시점이 핵심이다 |
| zh   | `需要你亲自确认` → `需要亲自确认`                           | 다른 문구는 `请`체인데 여기만 `你`체였다                             |
| zh   | `全部 {count} 项安全项目` → `安全检查清单的全部 {count} 项` | '안전 항목'이 막연했다. 화면의 목록 이름과 맞췄다                    |
| zh   | `载入` → `加载`                                             | 간체 표기 통일                                                       |
| en   | `CANNOT JUDGE` → `CANNOT DETERMINE`                         | 'judge'는 '재단하다'로도 읽힌다                                      |
| en   | `Result by check` → `Results for each check`                | 문법                                                                 |
| en   | `Matches your job` → `Job match`                            | 다른 검사 이름은 모두 명사구다                                       |
| en   | `Replace **it** with…` → `Fit a wheel…`                     | 문장 첫머리의 'it'이 무엇을 가리키는지 없었다                        |
| en   | `Redo the wheel only` → `Check the wheel again`             | '숫돌을 다시 만들라'로 읽힐 수 있었다                                |
| 전체 | `common.back`, `common.retake` 삭제                         | 어느 화면에서도 쓰지 않았다. 번역률만 부풀린다                       |

마지막 항목은 테스트로 막았다 (`쓰이지 않는 문구`). 화면을 번역할 때
키를 미리 만들지 말고, 쓸 때 만든다.

## 핵심 흐름 전체 번역 (2026-09-16)

"번역 파일이 있다"가 아니라 작업자가 고른 언어로 처음부터 끝까지 진행할 수 있게
하려고, 화면 코드에 박혀 있던 한국어를 모두 문구 키로 옮겼다.

- 규칙엔진의 사유 문장은 사유 코드로 옮겼다(위 표 아래 설명).
- 카메라·사진 형식·서버 오류는 한국어 문장을 그대로 띄우지 않고, 실패 종류로
  고른 언어의 문장을 고른다. 분석 서비스 오류는 상태 코드를 함께 보인다.
- 번역이 빠지거나 한국어가 섞이면 테스트가 막는다 — 빠진 키(타입 검사·`i18n.test.ts`),
  번역문 속 한글(`i18n.test.ts`), 화면 코드 속 한국어(`noHardcodedKorean.test.ts`),
  사유 문장과 엔진 문장의 어긋남(`checkText.test.ts`).
- 흐름 E2E(`src/e2e/languages.e2e.test.tsx`)가 영어·베트남어·인도네시아어·중국어로
  작업 선택부터 저장·이력까지 돌리며, 화면마다 한글이 섞였는지 본다(접힌 내용·
  aria-label·placeholder·탭 제목 포함). 실제 브라우저가 아니라 happy-dom이다.

용어는 아래 대조표에서 정한 말을 따랐다. 옮기다가 앞서 정한 말과 달라져 있던
곳 두 개를 찾아 맞췄다.

| 언어 | 고친 것                                      | 이유                                                                    |
| ---- | -------------------------------------------- | ----------------------------------------------------------------------- |
| vi   | 장비 상태 확인 `Nắp bảo vệ` → `Chụp bảo vệ`  | 9/2에 `nắp`을 고쳤는데, 나중에 붙은 장비 상태 문구에 다시 들어가 있었다 |
| id   | 장비 상태 확인 `pelindung` → `kap pelindung` | 같은 이유. 대조표의 용어는 `Kap pelindung`이다                          |

**이 작업도 원어민 검수를 대신하지 못한다.** 새로 옮긴 문장 — 특히 `reason.*`(검사
사유)와 `hazard.*`(작업별 위험사항) — 는 검수 목록에 함께 넘긴다.

## 검수자에게 물어봐야 할 것

고칠지 확신이 서지 않아 그대로 둔 것들이다. **이 목록을 검수와 함께 넘긴다.**

**모든 언어 공통 — 가장 중요한 질문**

> `verdict.compatible`(적합)이 그 언어에서 **"이 숫돌을 써도 안전하다"** 로 읽힙니까?
> 그렇게 읽힌다면 반드시 바꿔야 합니다. 이 앱은 라벨에 적힌 규격이 서로 맞는지만 봅니다.

**Tiếng Việt** — 현지 자료 대조를 마쳤다. 아래 한 가지만 남았다.

- `Đá mài`를 절단날에도 쓰고 있다. 절단날은 `đá cắt`이 더 정확하지 않나?
  앱은 숫돌 용도(절단/연삭)를 이미 알고 있으니 용도에 따라 말을 바꿀 수도 있다.
  다만 지금은 한 단어로 두었다 — 현지 자료에서 `đá mài`가 두 경우 모두에 쓰인다.
- 방호덮개를 `chụp bảo vệ`로 정했다. 자료마다 `vành bảo vệ`,
  `tấm chắn bảo vệ`, `bộ che chắn`도 쓴다. 어느 쪽이 현장에서 통하나?
- 절단날을 `đá mài dùng để cắt`처럼 풀어 적었다(촬영 화면 설명·위험사항).
  위의 `đá cắt` 질문과 함께 확인한다.

**Bahasa Indonesia** — 현지 자료 대조를 마쳤다. 아래만 남았다.

- 숫돌을 `batu gerinda`로 적었다. 자료에 `mata gerinda`도 많이 나온다.
  현장에서 어느 쪽을 더 쓰나?
- 절단날을 `batu gerinda potong`으로 적었다. `mata potong`이 더 통하나?

**中文** — 현지 자료 대조를 마쳤다. 아래만 남았다.

- 숫돌을 `砂轮`으로 적었다. 자료에 `砂轮片`, `磨片`, `切片`도 나온다.
  얇은 절단날에는 `砂轮片`이 더 맞지 않나?
- 절단날·연삭날을 `切割用砂轮`·`打磨用砂轮`으로 풀어 적었다. 위 질문과 함께 확인한다.

**English** — 용어는 OSHA 표기에 맞췄다. 아래만 남았다.

- `Wheel use`(숫돌 용도)와 `Job match`(작업 목적 일치)가 헷갈리지 않나?
  둘은 다른 검사다 — 앞은 라벨에 적힌 용도, 뒤는 오늘 작업과 맞는지다.
- 이 화면의 영어를 읽는 사람은 대개 영어가 모국어가 아니다.
  `SPECS MATCH`가 그 사람들에게도 바로 읽히나?
- `Wheel use`를 값 확인 화면의 항목 이름으로도 쓴다. 라벨에 적힌 용도라는 뜻이
  그대로 읽히나?

## 현지 자료 대조 (2026-09-02 ~ 09-03)

### Tiếng Việt

감으로 고르지 않으려고 베트남 현지 산업안전 자료와 Bosch 베트남 자료를 찾아 대조했다.

| 앱의 용어     | 뜻         | 대조 결과                                                            |
| ------------- | ---------- | -------------------------------------------------------------------- |
| `Máy mài`     | 그라인더   | ✅ 정식은 `máy mài góc`. 줄인 형태도 현지에서 통용                   |
| `Đá mài`      | 숫돌       | ✅ 현지 자료에서 쓴다 (`đĩa mài`도 함께 쓰임)                        |
| `tay cầm phụ` | 보조손잡이 | ✅ Bosch 베트남 자료의 표현 (`tay nắm phụ`도 같이 쓰임)              |
| `giật ngược`  | 반동       | ✅ 전동공구 kickback을 가리키는 말이 맞다                            |
| `nắp bảo vệ`  | 방호덮개   | ❌ **고침 → `chụp bảo vệ`.** `nắp`은 '뚜껑'이다. 어떤 자료도 안 쓴다 |
| `đánh bóng`   | 연마       | ❌ **고침 → `Công việc mài`.** `đánh bóng`은 '광내기'다              |

찾아본 곳: 베트남 산업안전 교육자료(máy mài góc cầm tay), Bosch 베트남
안전 안내, 전동공구 kickback 설명 자료.

### 中文

| 앱의 용어 | 뜻       | 대조 결과                                                                |
| --------- | -------- | ------------------------------------------------------------------------ |
| `角磨机`  | 그라인더 | ✅                                                                       |
| `防护罩`  | 방호덮개 | ✅ 중국어권 안전자료의 표준어                                            |

`反弹` → `回弹`이 이번에 가장 중요한 수정이다. 보조손잡이를 양손으로 잡는
이유는 **공구가 튀기 때문**인데, `反弹`으로 적으면 파편 이야기로 읽혀
문장의 인과가 끊긴다.

### English

| 앱의 용어      | 대조 결과                                                         |

| `kickback`     | ✅ 표준어                                                         |

장착 전에 확인하라. 이 앱의 RPM 검사가 하는 일이 정확히 그것이다.

및 홍콩 직업안전건강국 각마기 자료, OSHA 1926.303 / 1910.215, HSE HSG17.

안전보건공단이 **외국인노동자용 안전보건자료를 17개 언어로** 만들어 두었다.
베트남어 자료도 있고 지금도 갱신된다 (2026년 8월 자료까지 확인).

- 산업안전포털 → 산재예방 정보 → 안전보건 자료실 → **외국인 자료**
  <https://portal.kosha.or.kr/archive/cent-archive/foreign-arch/foreign-page1>
- 검색창에 `연삭`을 넣으면 베트남어 금속가공 자료가 나온다.

이걸 기준으로 삼는 이유가 세 가지다.

1. **작업자가 이미 그 말로 교육받았다.** 한국에서 일하는 베트남 노동자가
   보는 안전자료가 그것이다. 앱만 다른 단어를 쓰면 오히려 헷갈린다.
2. **공신력이 있다.** 논문에 "용어를 KOSHA 외국인노동자 자료에 맞췄다"고
   쓸 수 있다. 내가 고른 단어라고 쓰는 것과는 무게가 다르다.
3. **공짜고 지금 받을 수 있다.**

### 사람 검수는 그래도 필요하다

자료 대조는 단어를 맞춰줄 뿐, 문장이 자연스러운지는 알려주지 않는다.
특히 `action.*`은 현장에서 읽고 바로 움직여야 하는 명령문이다.

찾아볼 만한 곳:

- 교내 베트남 유학생 (공대면 더 좋다 — 공구 이름을 안다)
- 지역 외국인근로자지원센터 / 다문화가족지원센터 통역 담당
- 베트남 노동자를 고용 중인 사업장의 통역 담당자

물어볼 것은 이 문서의 "검수자에게 물어봐야 할 것"에 정리돼 있다.

## 구조

```
src/lib/i18n/
  messages/ko.ts   ★ 원본. 키를 여기서 정한다
  messages/en.ts, vi.ts, id.ts, zh.ts
  index.ts         useLocale() · translate()
  ruleLabel.ts     규칙엔진의 규칙 이름 → 문구 키
  checkText.ts     사유 코드 → 고른 언어의 사유 문장·비교 값
  format.ts        규격 요약·숫돌 조건·여유율 문장
  errors.ts        분석 실패 종류 → 오류 문장
  i18n.test.ts               번역 무결성
  checkText.test.ts          한국어 사유 = 엔진 문장 (글자까지)
  noHardcodedKorean.test.ts  화면 코드에 한국어를 직접 쓰지 않았는지
```

- **엔진은 번역을 모른다.** `engine.ts`는 계속 한국어 사유를 내고, 그 옆에 사유
  코드를 함께 낸다. 표시 언어는 판정과 상관이 없으므로 화면 쪽에서 붙인다.
  엔진은 순수 함수로 남는다(번역 모듈을 불러오지 않는다).
- 규칙 계층의 다른 파일(`requirement.ts`·`version.ts`)도 문장을 만들지 않는다.
  값이나 문구 키만 내고, 문장은 `format.ts`·화면이 붙인다.
- 언어는 `localStorage`(`wheelmatch.locale`)에 둔다. URL(`/en/...`)로 하지 않은
  이유는 화면이 다섯 개뿐이고 기록이 기기에만 남아 얻을 게 없기 때문이다.
- 서버 렌더 스냅샷은 항상 한국어다. 브라우저 값으로 서버를 그릴 수 없으므로
  고정해야 hydration에서 문구가 어긋나지 않는다.

## 문구를 고칠 때

1. `messages/ko.ts`를 먼저 고친다. 키가 곧 계약이다.
2. 나머지 4개 파일을 **같이** 고친다. `Messages` 타입이 키 누락을 막지만,
   내용이 옛날 문장으로 남는 것은 막지 못한다.
3. `npm test`를 돌린다. `i18n.test.ts`가 다음을 막는다.
   - 빠진 키 / 빈 문구 / 한국어에 없는 키
   - `{count}` 같은 자리표시자 불일치
   - 번역 안 한 채 한국어를 그대로 복사해둔 것, 번역문에 한글이 섞인 것
   - 엔진에 규칙을 추가하고 문구 키를 안 만든 것
   - 어느 화면에서도 쓰이지 않는 키
4. 컴포넌트에 한국어를 직접 쓰지 않는다. `noHardcodedKorean.test.ts`가 문자열·JSX의
   한국어를 찾아 막는다. 한국어가 남아도 되는 파일은 그 테스트의 허용 목록에
   이유와 함께 적는다.
5. 검사 사유 문장을 고치면 `engine.ts`의 문장과 `ko.ts`의 `reason.*`를 함께 고친다.
   한 글자라도 다르면 `checkText.test.ts`가 막는다. 새 분기를 만들면 `ReasonCode`에
   코드를 더한다 — 번역을 빠뜨리면 `checkText.ts`의 연결표가 타입 검사에서 막힌다.

## 검수 요청 시 전달할 것

- `src/lib/i18n/messages/<언어>.ts` 파일
- 대조용 `ko.ts`
- 다음 주의사항:
  - `verdict.compatible`은 **"사용해도 좋다"는 뜻이 되면 안 된다.** 이 앱은
    라벨에 적힌 규격이 서로 맞는지만 본다. 안전 승인이 아니다.
    (그래서 영어를 'OK to use'가 아니라 'SPECS MATCH'로 했다.)
  - `action.*`은 설명이 아니라 **명령문**이어야 한다. 현장에서 읽고 바로 움직인다.
  - `{count}`·`{wheel}`·`{type}` 같은 자리표시자는 그대로 둔다. 숫자나 이름이
    들어갈 자리다.
  - 한국어 문장의 `은(는)`은 조사 표시다. 앞 낱말에 맞춰 하나로 바뀐다.
    번역문에 옮기지 않는다.
