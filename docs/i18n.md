# 다국어 — 현재 상태와 남은 일

지원 언어: 한국어 · English · Tiếng Việt · Bahasa Indonesia · 中文(간체)

## 반드시 먼저 알아야 할 것

**한국어 외 4개 언어는 아직 검수를 받지 않았다.** 기계 번역이 아니라 사람이
읽을 수 있게 다듬은 문장이지만, 원어민이 확인한 적은 없다. 현장에 내보내기 전에
검수가 필요하다.

앱은 이 사실을 숨기지 않는다. 한국어가 아닌 언어를 고르면 화면에
"번역문은 검수 전입니다. 뜻이 갈리면 한국어 원문을 따르세요"가 뜬다
(`translation.notice`). 검수가 끝나기 전에는 이 문구를 지우지 마라.

## 어디까지 번역했나

| 화면 요소                           | 5개 언어  | 비고                   |
| ----------------------------------- | --------- | ---------------------- |
| 판정 (적합/부적합/판정불가) + 설명  | ✅        | 가장 중요한 문구       |
| 즉시 행동지침 (사용하지 마십시오 …) | ✅        | 부적합일 때 뜨는 조치  |
| 검사 항목 **이름**                  | ✅        | RPM 안전, 지름 호환 …  |
| 안전 체크리스트 4개 (제목 + 설명)   | ✅        | 체크해야 저장이 열린다 |
| 작업 직전 불꽃 방향 안내            | ✅        |                        |
| 면책 문구                           | ✅        |                        |
| 메인 화면 (작업 선택)               | ✅        |                        |
| 결과 화면 버튼·안내                 | ✅        | 재촬영, 저장, 오류     |
| 검사 항목 **사유 문장**             | ❌ 한국어 | 숫자와 아이콘은 그대로 |
| 작업별 위험사항 본문                | ❌ 한국어 | 기본 접힘, 보조 정보   |
| 촬영 화면 안내                      | ❌ 한국어 |                        |
| 점검 이력 화면                      | ❌ 한국어 | 작업자용 화면이 아니다 |

사유 문장을 남겨둔 이유: 항목 이름과 두 값(11000rpm / 8500rpm), ✅❌⚠ 아이콘만으로
무엇이 걸렸는지 읽힌다. 그리고 실제로 막힌 경우에는 **행동지침이 번역되어 있다.**
판단과 행동에 필요한 것은 번역돼 있고, 설명은 아직 한국어다.

## 자체 점검에서 고친 것 (2026-09-02)

번역을 처음부터 다시 읽으며 고친 것들이다. 원어민 검수를 대신하지는 못한다.

| 언어 | 고친 것                                                     | 이유                                                                 |
| ---- | ----------------------------------------------------------- | -------------------------------------------------------------------- |
| vi   | `kiểm duyệt` → `hiệu đính`                                  | **오역.** `kiểm duyệt`는 '검열'이다. 번역 검수는 `hiệu đính`이다     |
| vi   | `Trang đầu` → `Trang chủ`                                   | `Trang đầu`는 '첫 페이지'. 홈은 `Trang chủ`                          |
| vi   | `công trường` → `nơi làm việc`                              | `công trường`은 건설현장만 뜻한다. 원문 '사업장'은 공장도 포함한다   |
| id   | `kecepatan tepi` → `kecepatan keliling`                     | 원주속도의 정식 용어                                                 |
| zh   | `作业前` → `就在开始作业前`                                 | 원문 '작업 **직전**'의 시점이 빠져 있었다. 이 문구는 시점이 핵심이다 |
| zh   | `需要你亲自确认` → `需要亲自确认`                           | 다른 문구는 `请`체인데 여기만 `你`체였다                             |
| zh   | `全部 {count} 项安全项目` → `安全检查清单的全部 {count} 项` | '안전 항목'이 막연했다. 화면의 목록 이름과 맞췄다                    |
| zh   | `载入` → `加载`                                             | 간체 표기 통일                                                       |
| en   | `CANNOT JUDGE` → `CANNOT DETERMINE`                         | 'judge'는 '재단하다'로도 읽힌다                                      |
| en   | `Result by check` → `Results for each check`                | 문법                                                                 |
| en   | `Matches your job` → `Job match`                            | 다른 검사 이름은 모두 명사구다                                       |
| en   | `Replace **it** with…` → `Fit a wheel…`                     | 문장 첫머리의 'it'이 무엇을 가리키는지 없었다                        |
| en   | `Redo the wheel only` → `Check the wheel again`             | '숫돌을 다시 만들라'로 읽힐 수 있었다                                |
| 전체 | `common.back`, `common.retake` 삭제                         | 어느 화면에서도 쓰지 않았다. 번역률만 부풀린다                       |

마지막 항목은 테스트로 막았다 (`쓰이지 않는 문구`). 화면을 번역할 때
키를 미리 만들지 말고, 쓸 때 만든다.

## 검수자에게 물어봐야 할 것

고칠지 확신이 서지 않아 그대로 둔 것들이다. **이 목록을 검수와 함께 넘긴다.**

**모든 언어 공통 — 가장 중요한 질문**

> `verdict.compatible`(적합)이 그 언어에서 **"이 숫돌을 써도 안전하다"** 로 읽힙니까?
> 그렇게 읽힌다면 반드시 바꿔야 합니다. 이 앱은 라벨에 적힌 규격이 서로 맞는지만 봅니다.

**Tiếng Việt**

- `Đá mài`를 절단날에도 쓰고 있다. 절단날은 `đá cắt`이 맞지 않나?
  앱은 절단·연삭을 모두 다루는데 용어가 하나뿐이다.
- 방호덮개를 `nắp bảo vệ`로 적었다. `chụp bảo vệ`가 더 흔한 말 아닌가?
- 반동(kickback)을 `giật ngược`로 적었다. 현장에서 쓰는 말이 맞나?
- 연삭을 `đánh bóng`(광내기)으로 적었다. 연마 작업과 어감이 다르지 않나?

**Bahasa Indonesia**

- 반동을 `hentakan balik`으로 적었다. `tendangan balik`이 더 통하나?
- 방호덮개를 `Pelindung`만으로 적었다. `pelindung batu gerinda`가 필요한가?

**中文**

- 반동을 `反弹`으로 적었다. 전동공구 반동은 `反冲`이 맞나?
- 연삭을 `抛光`(광내기)으로 적었다. 연마 작업과 어감이 다르지 않나?

**English**

- `Wheel use`(숫돌 용도)와 `Job match`(작업 목적 일치)가 헷갈리지 않나?
  둘은 다른 검사다 — 앞은 라벨에 적힌 용도, 뒤는 오늘 작업과 맞는지다.

## 구조

```
src/lib/i18n/
  messages/ko.ts   ★ 원본. 키를 여기서 정한다
  messages/en.ts, vi.ts, id.ts, zh.ts
  index.ts         useLocale() · translate()
  ruleLabel.ts     규칙엔진의 규칙 이름 → 문구 키
  i18n.test.ts     번역 무결성
```

- **엔진은 건드리지 않았다.** `engine.ts`는 계속 한국어 문자열을 낸다.
  표시 언어는 판정과 상관이 없으므로 화면 쪽에서 붙인다. 엔진은 순수 함수로 남는다.
- 언어는 `localStorage`(`wheelmatch.locale`)에 둔다. URL(`/en/...`)로 하지 않은
  이유는 화면이 다섯 개뿐이고 기록이 기기에만 남아 얻을 게 없기 때문이다.
- 서버 렌더 스냅샷은 항상 한국어다. 브라우저 값으로 서버를 그릴 수 없으므로
  고정해야 hydration에서 문구가 어긋나지 않는다.

## 문구를 고칠 때

1. `messages/ko.ts`를 먼저 고친다. 키가 곧 계약이다.
2. 나머지 4개 파일을 **같이** 고친다. `Messages` 타입이 키 누락을 막지만,
   내용이 옛날 문장으로 남는 것은 막지 못한다.
3. `npm test`를 돌린다. `i18n.test.ts`가 다음을 막는다.
   - 빠진 키 / 빈 문구 / 한국어에 없는 키
   - `{count}` 같은 자리표시자 불일치
   - 번역 안 한 채 한국어를 그대로 복사해둔 것
   - 엔진에 규칙을 추가하고 문구 키를 안 만든 것

## 검수 요청 시 전달할 것

- `src/lib/i18n/messages/<언어>.ts` 파일
- 대조용 `ko.ts`
- 다음 주의사항:
  - `verdict.compatible`은 **"사용해도 좋다"는 뜻이 되면 안 된다.** 이 앱은
    라벨에 적힌 규격이 서로 맞는지만 본다. 안전 승인이 아니다.
    (그래서 영어를 'OK to use'가 아니라 'SPECS MATCH'로 했다.)
  - `action.*`은 설명이 아니라 **명령문**이어야 한다. 현장에서 읽고 바로 움직인다.
  - `{count}`는 그대로 둔다. 숫자가 들어갈 자리다.
